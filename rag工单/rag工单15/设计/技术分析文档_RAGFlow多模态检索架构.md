## 1. RAGFlow 原有检索流程分析

### 1.1 检索架构概览

RAGFlow 的检索系统由 `rag/nlp/search.py` 中的 `Dealer` 类实现，支持混合检索（向量 + BM25）。

```
用户提问 → Dealer.search()
  ├─ 向量检索：使用嵌入模型(BGE-M3/SILICONFLOW)编码查询
  ├─ BM25 关键词检索：基于 Elasticsearch 的文本匹配
  ├─ 混合加权：vector_similarity_weight * 向量分 + (1-weight) * BM25分
  └─ 返回 Top-K 个 chunk
```

**关键文件**：
- `rag/nlp/search.py:37` — `Dealer` 类，检索核心
- `rag/nlp/search.py:573` — `retrieval()` 方法，异步检索入口
- `rag/nlp/query.py` — 查询构建与分词
- `rag/svr/task_executor.py:1364` — `do_handle_task()`，任务编排

### 1.2 查询处理流程

```
query → rag_tokenizer.tokenize() → ES bool query
       ├─ match: content_with_weight (向量检索用)
       ├─ match: content_ltks (BM25 关键词匹配)
       └─ 按 kb_id + tenant_id 过滤
```

**问题**：查询处理**不区分文本问题和图文混合问题**，统一使用原始问题文本进行检索。

### 1.3 多模态支持现状

RAGFlow 的 DeepDoc 模块在解析阶段会：
- OCR 识别文本
- 检测并描述图片 (`figure_parser.py`)
- 提取表格结构 (`table_structure_recognizer.py`)

但在**检索阶段**，图片描述文本与普通文本块**混合存储、同等对待**，没有：
- 图像感知的查询增强
- 图文块的优先级区分
- 跨模态特征融合

### 1.4 重排 (Re-Rank)

RAGFlow 支持可选的 ReRank 模型（通过 `rerank_id` 配置），在初检后对候选集进行精细化排序。但默认不启用，且与检索流程松耦合。

## 2. 瓶颈诊断

### 2.1 故障1：检索无关

**场景**：用户提问"编号13的部件相对于编号12..."

**现象**：
- 系统仅通过"部件"、"编号"等泛文本关键词检索
- 返回大量提及部件编号但不含"图3"的文本块
- 遗漏关键图纸所在的页面

**根因**：
1. 查询理解缺失 — 未识别"图3"、"第11页"等视觉引用
2. ES 中文分词使用 `whitespace` 分析器，无法正确分词中文
3. 向量检索对专利技术图纸的语义理解有限

### 2.2 故障2：图文割裂

**场景**：即使检索到包含图3的页面

**现象**：
- 检索结果中图像块和文本块混合排列
- LLM 无法从纯文本描述中推断部件空间关系
- 缺少图像描述文本的权重提升机制

**根因**：
1. 检索不区分图文块类型，图像块没有优先级
2. 缺少跨模态重排机制
3. Prompt 模板未指示 LLM 优先参考图纸描述

### 2.3 瓶颈总结

| 层级 | 瓶颈 | 影响 |
|------|------|------|
| 查询理解 | 未识别视觉引用 | 检索方向偏离 |
| 召回 | 单路文本检索 | 图像信息未被充分利用 |
| 融合 | 无多路融合策略 | 文本/图像结果割裂 |
| 排序 | 无跨模态重排 | 图纸页面排名靠后 |
| 提示工程 | 未区分图文问题 | LLM 忽略视觉线索 |

## 3. 优化方案设计

### 3.1 优化架构

```
优化后的检索流程：

用户提问 → QueryAnalyzer
  ├─ 检测视觉引用（图/页/部件）
  ├─ 构建增强查询（+图纸描述）
  └─ 判定查询类型（text / image_text）
       │
       ├─ 文本检索（原始查询，向量+BGE-M3）
       ├─ 图像增强检索（增强查询，向量+BGE-M3）
       │
       └─ RRF 倒数排名融合
            │
            └─ Cross-Modal Reranker
                 ├─ 图表页面加分（+20%）
                 ├─ 精确页码匹配（+30%）
                 └─ 部件编号匹配（+10%）
                      │
                      └─ QA Generator（优化Prompt）
                           ├─ 图文问题特殊提示
                           ├─ 【含图纸】标记优先
                           └─ 部件名称↔编号映射
```

### 3.2 各模块设计

#### 模块1：QueryAnalyzer（查询理解）

**实现**：`研发/query_analyzer.py`

- 正则检测：`图\s*(\d+)` → 图表引用
- 正则检测：`第\s*(\d+)\s*页` → 页码引用
- 正则检测：`(?:编号|部件)\s*(\d+)` → 部件引用
- 增强查询 = 原始问题 + "【图文检索】" + 视觉引用描述
- 查询分类：`text` vs `image_text`

#### 模块2：Dual-Channel Retriever（双路检索）

**实现**：`研发/retriever.py`

- **路1-文本检索**：使用原始问题向量搜索，BGE-M3 编码，余弦相似度
- **路2-图像增强检索**：使用增强查询向量搜索，加权包含"图"关键词的页面
- **RRF融合**：`score = Σ 1/(k + rank_i)`，k=60，两路等权融合

#### 模块3：Cross-Modal Reranker（跨模态重排）

**实现**：`研发/reranker.py`

| 策略 | 条件 | 权重 |
|------|------|------|
| 图表页面优先 | `has_figure=True` | ×1.2 |
| 精确页码匹配 | 查询含页码引用 | ×1.3 |
| 部件编号匹配 | 查询含部件引用 | ×1.1 |
| 文本块默认 | 无匹配 | ×1.0 |

#### 模块4：Prompt Engineering（提示工程）

**实现**：`研发/qa_generator.py`

- 基础提示：专业专利文档分析助手
- 图文问题扩展：优先参考【含图纸】标记的上下文
- 部件编号优先：当询问部件时，优先回答编号而非名称
- 格式控制：简洁回答，不加解释

### 3.3 配置参数

| 参数 | 默认值 | 说明 |
|------|--------|------|
| RETRIEVE_TOP_K | 10 | 检索候选数 |
| RERANK_TOP_K | 5 | 重排后保留数 |
| RRF_K | 60 | RRF融合常数 |
| TEXT_WEIGHT | 0.5 | 文本检索权重 |
| IMAGE_WEIGHT | 0.5 | 图像检索权重 |

## 5. 优化前后对比

### 5.1 功能对比

| 维度 | 优化前（RAGFlow默认） | 优化后（本系统） |
|------|-------------------|----------------|
| 查询理解 | 不分类型，原文检索 | 自动识别视觉引用，查询增强 |
| 召回策略 | 单路混合检索 | 双路召回 + RRF融合 |
| 排序 | 向量+BM25混合 | 跨模态重排（图表/页码优先） |
| 提示工程 | 通用提示 | 图文专项提示 + 部件映射 |
| 检索精度 | 图文问题Top-1命中率低 | Q3-Q6 Top-1全中page_11 |
