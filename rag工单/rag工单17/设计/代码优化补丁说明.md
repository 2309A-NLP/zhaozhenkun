## 补丁清单

### 补丁1: `common/resource_cache.py` (新增文件)

**目的**: 解决 LLMBundle 每次请求重复创建的问题（瓶颈1/2）

**内容**:
- `LLMBundleCache`: 进程级 LLMBundle 缓存，基于 (tenant_id, factory, model_name, model_type) 键值，TTL 300秒
- `LangfuseCache`: 租户级 Langfuse 客户端缓存，TTL 600秒
- `ChatConcurrencyLimiter`: asyncio.Semaphore 实现的并发限流器，默认最多10个并发
- `get_or_create_bundle()`: 便捷函数，先查缓存再创建

**影响**: 
- 从每请求创建5+个LLMBundle降低为每TTL周期创建1次
- 从每请求创建1个Langfuse客户端降低为每租户复用1个

### 补丁2: `api/db/services/dialog_service.py` (修改)

**变更点**:

| 行号 | 变更 | 目的 |
|------|------|------|
| import区域 | 添加 `from common.resource_cache import ...` | 引入缓存模块 |
| `get_models()` | `LLMBundle()` → `get_or_create_bundle()` | 使用缓存的模型实例 |
| `async_chat_solo()` | `LLMBundle()` → `get_or_create_bundle()` | 同上 |
| `async_chat()` Langfuse初始化 | 添加 `LangfuseCache.get_instance()` 缓存逻辑 | 复用Langfuse连接 |
| `async_chat()` 入口 | 添加 `await limiter.acquire()` | 并发控制 |
| 各return点 | 添加 `limiter.release()` | 释放并发槽位 |

### 补丁3: `api/db/db_models.py` (修改)

**变更点**:
