# 教育 Agent 需求分析与软件架构设计

## 一、项目背景
- 面向高职院校教学数字化转型场景，解决教师备课负担重、学生学习差异大、教学评估闭环弱的问题。
- 本次工单以教学侧优先，重点落地智能备课、智能助教、教学评估、个性化学习四类核心能力。
- 交付目标为可运行、可演示、可二次扩展的现代化教育 Agent 原型。

## 二、需求分析
### 1. 目标用户
- 教师：需要快速生成教案、练习、讲解素材与课堂评价建议。
- 学生：需要多轮答疑、错题讲解、个性化学习路径与阶段学习反馈。
- 教研管理者：需要可视化了解教学能力覆盖与学习数据沉淀情况。

### 2. 主要功能场景
- 智能备课：输入课程、主题、目标后自动生成教学方案、互动设计与练习任务。
- 智能助教：支持课堂答疑、课后问答、知识点解释、多轮对话连续理解。
- 教学评估：支持文本作业与图片作业的评估、讲解与纠错建议。
- 个性化学习：基于学生画像、薄弱点与目标生成学习周计划、教师跟进建议与学习报告。

## 三、软件设计架构
### 1. 总体架构
- 前端展示层：Jinja2 模板 + 原生 JavaScript + 现代化样式系统。
- 接口编排层：Flask 路由统一接收页面请求并分发到场景服务。
- 业务服务层：备课、助教、评估、个性化学习四类服务独立实现。
- 数据与模型层：本地 JSON 示例数据 + DeepSeek 文本模型 + 千问多模态模型。

### 2. 详细分层说明
- 页面层：负责场景切换、表单提交、结果渲染。
- API 层：负责参数解析、错误处理、标准化响应。
- 编排层：按场景协调知识检索、会话记录、模型调用、多模态处理。
- 服务层：按单一业务职责拆分，便于控制每个 Python 文件不超过 300 行。
- 仓储层：统一处理课程、知识库、学生画像、会话与结果落盘。

## 四、各场景技术选型分析
- 智能备课：文本大模型 + 课程知识片段检索，适合生成结构化教学方案。
- 智能助教：文本大模型 + 最近会话上下文保留，适合多轮答疑。
- 教学评估：文本模型处理普通作答，多模态模型处理作业拍照、题目截图。
- 个性化学习：学生画像 + 知识片段 + 文本模型，适合输出周计划与教师建议。

## 五、数据安全与合规
- 模型密钥只通过环境变量注入，不写入源码与前端。
- 上传图片仅允许常见图像格式，并限制单文件大小。
- 示例数据使用本地演示数据，不包含真实学生敏感信息。
- 后续若接入真实校务系统，应增加脱敏、权限控制、日志审计与数据保留策略。

## 六、实施建议
- 第一步：按当前 MVP 部署原型，完成教学场景演示闭环。
- 第二步：接入校本课程资源、题库、教案模板和真实教学数据。
- 第三步：扩展语音交互、数字人播报和教研大屏。
- 资源规划：前端 1 人、后端 1 人、提示词/知识整理 1 人、测试 1 人可在短周期内完成升级。
- 工时建议：原型 1~2 人日，知识与交互增强 2~4 人日，正式化接入视数据接口复杂度确定。
