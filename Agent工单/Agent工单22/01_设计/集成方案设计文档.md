# 基于 mem0 的多领域智能体长期记忆系统 — 集成方案设计与记忆建模文档

> 工单编号：人工智能-Agent数字人-22 | 版本 V1.1 | 2026年2月

---

## 1. 系统概述

### 1.1 项目背景

当前部署的医疗、文旅、教育等领域智能体普遍缺乏跨对话的长期记忆能力，每次交互都是独立"快照"，无法实现个性化与连续性服务。本系统基于开源记忆管理库 **mem0**，为各领域智能体植入统一、可扩展的长期记忆层。

### 1.2 核心能力

| 能力 | 描述 |
|------|------|
| **自动摘要** | 对话结束时自动生成摘要，合并至长期记忆 |
| **语义存储** | 基于 pgvector 向量数据库存储记忆，支持语义检索 |
| **上下文检索** | 新对话开始时检索最相关的历史记忆，注入智能体上下文 |
| **多领域隔离** | 通过 agent_id + user_id 实现医疗/文旅/教育领域数据隔离 |

## 2. 系统架构

```
┌─────────────────────────────────────────────────┐
│                   智能体层                         │
│     医疗Agent    │   文旅Agent    │   教育Agent     │
│                   (已有业务系统)                    │
└──────────────────────┬──────────────────────────┘
                       │ REST API (HTTP)
┌──────────────────────▼──────────────────────────┐
│              记忆桥接服务 (agent_bridge.py)        │
│  POST /api/memory/process  ← 存储对话记忆         │
│  GET  /api/memory/context  ← 检索历史上下文        │
│  POST /api/chat            ← LLM对话(带记忆)       │
└──────────────────────┬──────────────────────────┘
                       │
┌──────────────────────▼──────────────────────────┐
│              记忆处理层 (memory_processor.py)      │
│  extractor → 提取关键信息 (DeepSeek LLM)          │
│  summarizer → 生成对话摘要                         │
│  retriever → 语义搜索历史记忆                       │
└──────────────────────┬──────────────────────────┘
                       │
┌──────────────────────▼──────────────────────────┐
│              记忆基础设施层                         │
│  mem0 REST API (localhost:8888)                  │
│  ├── pgvector (向量存储+语义检索)                   │
│  ├── Neo4j (知识图谱)                              │
│  └── fastembed (本地嵌入模型 BAAI/bge-small)       │
└─────────────────────────────────────────────────┘
```

### 2.1 技术选型

| 组件 | 选型 | 说明 |
|------|------|------|
| 记忆管理 | mem0 v2.0.11 | 开源长期记忆框架 |
| LLM | DeepSeek v4-flash | 信息提取+摘要+对话 |
| 向量存储 | pgvector (PostgreSQL) | 生产级向量检索 |
| 嵌入模型 | fastembed (bge-small-en-v1.5) | 本地运行，384维 |
| 知识图谱 | Neo4j 5 Enterprise | 实体关系存储 |
| API框架 | FastAPI + uvicorn | 高性能异步API |

### 2.2 数据流

```
对话结束 → agent调用POST /api/memory/process
         → extractor用LLM提取关键信息
         → summarizer用LLM生成摘要
         → mem0存储摘要+原文到pgvector
         → 返回success

新对话开始 → agent调用GET /api/memory/context?query=...
           → retriever在pgvector中语义搜索
           → 返回Top-K相关记忆
           → agent将记忆注入system prompt
           → 智能体表现为"有记忆力"
```

## 3. 多领域记忆 Schema 建模

### 3.1 医疗领域

| 字段 | 类型 | 说明 | 必填 |
|------|------|------|------|
| patient_id | string | 患者唯一标识 | ✅ |
| chief_complaint | string | 主诉症状 | ✅ |
| diagnosis_history | list | 历史诊断记录(日期/疾病/医生) | - |
| medication_records | list | 用药记录(药名/剂量/频次/起止) | - |
| follow_up_notes | list | 随访记录(日期/要点/建议) | - |
| health_goals | list | 健康目标 | - |
| allergies | list | 过敏史 | - |

**写入触发**: consultation_end / prescription_issued / diagnosis_made
**读取触发**: consultation_start / patient_asks_history
**保留策略**: 默认2年, 关键信息5年

### 3.2 文旅领域

| 字段 | 类型 | 说明 | 必填 |
|------|------|------|------|
| user_id | string | 用户唯一标识 | ✅ |
| preferred_destinations | list | 感兴趣的目的地 | - |
| activity_preferences | list | 偏好活动(徒步/博物馆/美食等) | - |
| travel_history | list | 历史旅行(目的地/日期/评分) | - |
| budget_preference | string | 消费偏好(经济/舒适/豪华) | - |
| companion_info | dict | 同行人信息 | - |
| dietary_constraints | list | 饮食限制 | - |

**写入触发**: trip_plan_completed / user_expresses_preference
**读取触发**: new_trip_inquiry / destination_recommendation
**保留策略**: 默认1年, 旅行历史3年

### 3.3 教育领域

| 字段 | 类型 | 说明 | 必填 |
|------|------|------|------|
| student_id | string | 学生唯一标识 | ✅ |
| course_progress | dict | 各课程学习进度 | ✅ |
| knowledge_graph | dict | 知识掌握图谱(1-5级) | - |
| weak_points | list | 易错知识点 | - |
| learning_style | string | 学习风格(视觉/听觉/动手/阅读) | - |
| interaction_history | list | 历史问答记录 | - |
| study_goals | list | 学习目标 | - |

**写入触发**: lesson_completed / quiz_submitted
**读取触发**: session_start / new_question_asked
**保留策略**: 默认1年(一学年), 薄弱点半年刷新

## 4. 记忆处理器设计

### 4.1 关键信息提取器 (extractor.py)

使用 DeepSeek LLM + 领域定制提示词，从多轮对话中自动提取结构化信息。
支持 JSON 容错解析（Markdown代码块、裸JSON、截断文本）。

### 4.2 记忆摘要生成器 (memory_processor.py)

在对话结束时调用 LLM 生成摘要，并与历史摘要合并更新。
Summary cache 保存在内存中减少重复计算。

### 4.3 相关性检索器 (memory_processor.py)

基于 fastembed (bge-small-en-v1.5, 384维) 向量的语义搜索。
返回 Top-K 相关记忆，构建自然语言上下文注入智能体 system prompt。

## 5. 与已有智能体集成方案

### 5.1 集成步骤

1. 在已有智能体的 `对话结束` 事件中调用 `POST /api/memory/process`
2. 在智能体的 `对话开始` 事件中调用 `GET /api/memory/context`，获取历史上下文
3. 将返回的 `context_prompt` 注入到 LLM 的 system prompt 中
4. 智能体回复时自动体现对用户历史的了解

### 5.2 集成示例（伪代码）

```python
import requests
API = "http://localhost:8008"

# 对话开始时检索历史
ctx = requests.get(f"{API}/api/memory/context",
    params={"domain":"medical","user_id":"PAT001","query":current_question})
history_context = ctx.json()["data"]["context_prompt"]

# 注入到LLM的system prompt
system_prompt = f"你是医疗助手。\\n【患者历史】\\n{history_context}"
response = llm.chat(system_prompt + user_message)

# 对话结束后存储
requests.post(f"{API}/api/memory/process", json={
    "domain":"medical", "user_id":"PAT001",
    "conversation": full_conversation_text
})
```
