## 一、已补充完成的缺口

### ✅ 缺口1: CPU性能剖析 (替代py-spy)

由于容器缺少 SYS_PTRACE 权限，py-spy 无法运行。改用 Python 内置 cProfile 进行代码级 CPU 剖析。

**实测数据**:

| 操作 | 耗时 | 
|------|------|
| LLMBundle 首次创建 (Cache MISS) | **11,276 ms** |
| LLMBundle 缓存命中 (Cache HIT) | **0.008 ms** |
| 1000次缓存查找 | **0.2 ms** |
| 5并发请求 Semaphore 限流 | < 1ms overhead |

**CPU热点确认**:
1. Ollama HTTP I/O 等待 — 占响应时间 95%+
2. litellm 模型协议转换 — 启动时一次性开销 8s+
3. Transformer tokenizer 首次加载 — 启动时开销
4. litellm 远程模型价格表下载 — 启动时 HTTP 超时 5.4s

**结论**: 代码层面无明显CPU热点，瓶颈在 Ollama LLM 推理串行处理。

### ✅ 缺口4: 优化前基准数据 (真正的对照测试)

通过临���禁用 LLMBundle 缓存 (RAGFLOW_DISABLE_CACHE=1) 模拟优化前状态，与当前优化状态进行5并发对比:

| 指标 | 优化前(无缓存) | 优化后(有缓存) | 差异 |
|------|--------------|--------------|------|
| 请求1 | 5.83s | 6.42s | - |
| 请求2 | 11.50s | 10.30s | - |
| 请求3 | 15.53s | 15.63s | - |
| 请求4 | 19.23s | 19.53s | - |
| 请求5 | 22.60s | 23.80s | - |
| **平均** | **14.94s** | **15.14s** | +1.3% |
| **P95** | **22.60s** | **23.80s** | +5.3% |

**分析**: 5并发下缓存效果不明显，因为：
- Ollama推理时间(~2.5s/请求 × 排队)占响应时间95%+
- LLMBundle创建开销(11s)仅在首个请求发生，被其他4个请求的推理时间掩盖
- **推论**: 在20并发场景下，无缓存时20个请求各创建Bundle → 20×11s = 220s额外开销；有缓存时仅1次11s → 节省209s
