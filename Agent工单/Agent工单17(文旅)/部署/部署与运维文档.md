## 二、快速部署

### 2.1 克隆项目
```bash
git clone https://github.com/infiniflow/ragflow.git
cd ragflow
```

### 2.2 应用工单17优化补丁

```bash
# 将补丁文件复制到项目目录
cp /path/to/rag工单17/patches/common_resource_cache.py ragflow/common/resource_cache.py

# 应用修改（或手动合并以下文件）：
# - api/db/services/dialog_service.py
# - api/db/db_models.py
```

### 2.3 启动服务（使用优化后的配置）
```bash
cd docker

# 方式1：使用优化后的docker-compose配置
cp /path/to/rag工单17/docker-compose-optimized.yml .
docker compose -f docker-compose-optimized.yml up -d

# 方式2：在原有基础上设置资源限制
docker compose -f docker-compose.yml up -d
docker update --cpus="4" --memory="8g" ragflow-server
docker update --cpus="4" --memory="8g" ragflow-task-executor
```

### 2.4 验证部署
```bash
# 检查服务状态
docker compose ps

# 查看日志
docker logs -f ragflow-server

# 健康检查
curl http://localhost:9380/api/v1/system/healthz
```

## 三、关键优化配置说明

### 3.1 LLMBundle 缓存

新增模块: `common/resource_cache.py`

```python
from common.resource_cache import get_or_create_bundle, LLMBundleCache, LangfuseCache

# 使用缓存的 LLMBundle（替代直接 LLMBundle() 构造）
chat_mdl = get_or_create_bundle(tenant_id, model_config)

# 查看缓存状态
cache = LLMBundleCache.get_instance()
print(f"Cached bundles: {len(cache)}")

# 手动清理缓存（部署后或模型配置变更时）
cache.clear()
```

**环境变量**:
- `LLM_BUNDLE_CACHE_TTL`: 缓存过期时间，默认300秒
- `LLM_BUNDLE_CACHE_MAX_SIZE`: 最大缓存条目，默认64

### 3.2 并发控制

```python
from common.resource_cache import ChatConcurrencyLimiter

# 默认最大10个并发聊天请求
limiter = ChatConcurrencyLimiter.get_instance(max_concurrent=10)
```

可通过环境变量调整:
- `MAX_CONCURRENT_CHAT`: 最大并发聊天请求数，默认10

### 3.3 数据库连接池

在 `api/db/db_models.py` 的 `BaseDataBase` 类中已配置:

```python
pool_config = {
    'max_retries': 5,
    'retry_delay': 1,
    'max_connections': 20,      # 最大连接数
    'stale_timeout': 300,       # 连接过期时间(秒)
}
```

### 3.4 容器资源限制

| 服务 | CPU限制 | 内存限制 | 说明 |
|------|---------|---------|------|
| API Server | 4核 | 8GB | 处理HTTP请求 |

## 四、日常运维

### 4.1 监控命令

```bash
# 容器资源使用
docker stats

# GPU使用（如有GPU）
watch -n 2 nvidia-smi

# API日志
docker logs -f --tail=100 ragflow-server

# Redis队列长度
docker exec ragflow-redis redis-cli LLEN task_queue

# 数据库连接数
docker exec ragflow-mysql mysql -u root -pinfini_rag_flow -e "SHOW PROCESSLIST;"
```

### 4.2 性能排查

```bash
# CPU热点采样（如果py-spy可用）
docker exec ragflow-server py-spy record -o /tmp/profile.svg --pid 1 --duration 30
docker cp ragflow-server:/tmp/profile.svg ./profile.svg

# 内存分析
docker exec ragflow-server python -c "
from common.resource_cache import LLMBundleCache
cache = LLMBundleCache.get_instance()
print(f'LLMBundle cache size: {len(cache)}')
"

# 查看慢日志
docker logs ragflow-server 2>&1 | grep -E "took [0-9]+\\.[0-9]+s" | tail -20
```

### 4.3 常见问题

**Q: 服务响应变慢**
1. 检查并发数: `docker logs ragflow-server | grep "concurrent"`
2. 检查LLMBundle缓存: 是否缓存命中
3. 检查数据库连接: `SHOW PROCESSLIST`

**Q: 内存持续增长**
1. 检查LLMBundle缓存大小: `LLMBundleCache.get_instance().__len__()`
2. 检查Langfuse缓存: `LangfuseCache.get_instance()._cache.keys()`
3. 手动清理: `LLMBundleCache.get_instance().clear()`

**Q: 服务启动失败**
1. 检查MySQL/Redis/ES是否已启动
2. 检查端口冲突: `netstat -tlnp | grep 9380`
3. 查看完整日志: `docker logs ragflow-server`

### 4.4 定时维护（建议）

每日:
- 检查容器运行状态
- 监控内存使用趋势

每周:
- 清理过期日志: `docker exec ragflow-server find /ragflow/logs -name "*.log" -mtime +7 -delete`
- 检查磁盘空间: `df -h`

每月:
- 重启服务释放碎片: `docker compose restart`
- 清理LLMBundle缓存: 服务重启后自动清理
