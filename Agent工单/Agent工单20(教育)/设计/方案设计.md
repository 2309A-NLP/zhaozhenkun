# 工单20 面试AI复盘 方案设计

## 1. 目标说明
本项目严格围绕工单20“面试AI复盘”核心需求实现，不将“简历投递情况分析”作为本次交付核心。

## 2. 功能范围
- 面试列表展示：学生、岗位名称、面试轮次/形式、面试城市/时间、上报人、上报时间、面试AI复盘。
- 学生记录查看：点击学生姓名进入面试记录详情。
- 批量导入：老师通过 JSON 模板批量导入学生面试记录。
- 来源区分：通过 `source_type` 和 `reporter_name` 区分教师导入与学生填报。
- 学生修改规则：仅支持两天内或状态为“待完善”的记录修改。
- 面试AI复盘：存在录音或录音转写文本时展示入口。
- 复盘详情：总体评价、自我介绍点评、问题解析、AI优化版对话与原始记录对照。
- 模型切换：前端支持 DeepSeek 与千问切换。

## 3. 技术架构
- 前端展示层：Jinja2 模板 + 原生 JavaScript + CSS。
- 接口编排层：Flask 路由统一处理页面与 API 请求。
- 业务服务层：仓储服务、音频服务、评分服务、复盘服务、模型服务。
- 数据存储层：本地 JSON 持久化面试记录、知识库和复盘缓存。
- 模型接入层：OpenAI 兼容协议接入 DeepSeek 与千问。

## 4. 数据流说明
1. 老师在首页查看面试列表。
2. 老师可使用导入模板批量导入面试记录。
3. 学生姓名可点击进入详情页查看或按规则修改记录。
4. 若存在录音，页面显示“面试AI复盘”入口。
5. 复盘流程优先读取录音转写与完整面试文本。
6. 本地规则先完成问题抽取、知识点匹配、评分和建议生成。
7. 选中的模型再对总体评价、自我介绍点评和建议进行增强。
8. 最终结果写入缓存并展示在复盘详情页。

## 5. 模块设计
- `研发/app.py`：应用入口与 Flask 工厂。
- `研发/config.py`：配置读取与目录初始化。
- `研发/routes.py`：页面和 API 路由注册。
- `研发/services/repository.py`：本地数据读写与编辑规则控制。
- `研发/services/scoring_service.py`：问题抽取、知识点匹配、本地评分。
- `研发/services/llm_service.py`：DeepSeek/千问文本增强。
- `研发/services/audio_service.py`：录音上传和兼容 ASR 转写。
- `研发/services/review_service.py`：复盘结果编排与缓存。

## 6. 接口设计
- `GET /`：面试列表页。
- `GET /interviews/<id>`：面试记录详情页。
- `GET /reviews/<id>?provider=deepseek|qwen`：复盘详情页。
- `GET /api/health`：健康检查。
- `GET /api/models`：模型状态。
- `GET /api/interviews`：面试记录列表接口。
- `POST /api/interviews/import`：批量导入接口。
- `POST /api/interviews/<id>`：记录编辑接口。
- `POST /api/interviews/<id>/audio`：录音上传接口。
- `POST /api/reviews/<id>`：生成复盘接口。

## 7. 数据结构
核心记录字段如下：
- `id`
- `student_name`
- `position_name`
- `interview_round`
- `interview_form`
- `interview_city`
- `interview_time`
- `reporter_name`
- `report_time`
- `source_type`
- `status`
- `self_intro`
- `full_transcript`
- `audio_text`
- `audio_file_name`
- `question_answers`

## 8. UML 文字流程
```text
老师/学生 -> Flask页面 -> 仓储服务 -> 本地JSON
录音上传 -> 音频服务 -> 本地文件/兼容ASR
复盘请求 -> 评分服务 -> 模型增强服务 -> 复盘缓存 -> 复盘详情页
```
