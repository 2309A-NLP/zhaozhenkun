## 1. WebSocket 协议 vs HTTP 协议

### 1.1 协议对比

| 维度 | WebSocket | HTTP |
|------|-----------|------|
| **连接方式** | 全双工长连接 | 请求-响应短连接 |
| **通信方向** | 双向实时通信 | 客户端→服务端单向请求 |
| **适用场景** | 实时语音识别、聊天、游戏 | 数据查询、文件上传、页面加载 |
| **延迟** | 低延迟（毫秒级） | 较高（每次请求建立连接） |
| **开销** | 首次握手后无额外头部 | 每次请求带完整 HTTP 头 |
| **状态** | 有状态 | 无状态 |
| **协议升级** | HTTP Upgrade → ws:// | 无 |

### 1.3 通义听悟 WebSocket 协议细节

- **端点:** `wss://tingwu-realtime-cn-beijing.aliyuncs.com/api/ws/v1`
- **鉴权:** Token（AK/SK HMAC-SHA1 签名，Base64 编码）
- **音频格式:** PCM 16kHz, 16bit, 单声道
- **消息格式:** JSON header + payload（二进制音频帧独立发送）
- **心跳:** ping_interval=20s

## 2. 异步编程 & 回调 & 多线程

### 2.1 异步编程 (asyncio)

```python
# 本项目中 asyncio 的应用
import asyncio

# 1. WebSocket 异步通信
async def realtime_asr_ws(ws: WebSocket):
    await ws.accept()
    async for result in tingwu.realtime_asr(audio_generator()):
        await ws.send_text(json.dumps(result))

# 2. 后台任务
asyncio.create_task(_do_postprocess(task_id, transcript))

# 3. 线程池执行同步阻塞代码
result = await loop.run_in_executor(None, sync_function, args)
```

**为什么用 asyncio？**
- WebSocket 连接是异步的，需要同时处理音频发送和结果接收
- 非阻塞 I/O 避免阻塞 FastAPI 的事件循环
- 协程切换比线程切换开销更小

### 2.2 回调 URL 机制

```
┌────────────────────────────────────────────────────────┐
│  回调方式 (Callback)                                    │
├────────────────────────────────────────────────────────┤
│                                                        │
│  1. 创建任务时提供 callback_url：                       │
│     POST /api/asr/tingwu/create?callback_url=...        │
│                                                        │
│  2. 通义听悟处理完成后 → POST 到 callback_url：         │
│     { "task_id": "xxx",                                │
│       "status": "completed",                           │
│       "result": { "summary": "...", ... } }            │
│                                                        │
│  3. 本项目回调接收端点：                                │
│     POST /api/asr/callback                             │
│                                                        │
│  优点: 无需轮询，节省带宽，实时性高                      │
│  缺点: 需要公网可达的回调 URL，调试不便                  │
└────────────────────────────────────────────────────────┘
```

### 2.3 轮询方式

```
┌────────────────────────────────────────────────────────┐
│  轮询方式 (Polling)                                     │
├────────────────────────────────────────────────────────┤
│                                                        │
│  1. 创建任务:                                          │
│     POST /api/asr/task/create                          │
│     → { "task_id": "abc123" }                          │
│                                                        │
│  2. 前端每2秒轮询:                                      │
│     GET /api/asr/task/abc123                           │
│     → { "status": "processing" }  // 继续等            │
│     → { "status": "done", "result": {...} }  // 完成   │
│                                                        │
│  优点: 实现简单，无需公网 IP                            │
│  缺点: 频繁请求消耗带宽，有查询延迟                     │
│                                                        │
│  实现: setInterval(() => fetch(task_url), 2000)         │
└────────────────────────────────────────────────────────┘
```

### 2.5 三种异步模式对比

| 模式 | 适用场景 | 本项目中位置 |
|------|---------|------------|
| **asyncio 协程** | I/O 密集（WebSocket, HTTP） | WebSocket ASR, FastAPI 请求处理 |
| **回调** | 外部服务完成通知 | `POST /api/asr/callback` |
| **线程池** | CPU 密集/同步阻塞代码 | LLM API 调用, SadTalker 视频生成 |

## 3. 通义听悟任务状态机

```
  NEW ──→ QUEUEING ──→ RUNNING ──→ SUCCESS
  │                                  │
  └──────────────────────────────────┘
              (任意阶段)
              ──→ FAILED
```

| 状态 | 说明 | 下一步 |
|------|------|--------|
| NEW | 已创建，等待调度 | → QUEUEING |
| QUEUEING | 排队中 | → RUNNING |
| RUNNING | 处理中 | → SUCCESS/FAILED |
| SUCCESS | 完成（Result 字段有值） | 终态 |
| FAILED | 失败 | 检查 Message 字段 |
