# ADSD 多角色对话系统 — 优化文档

## 1. 性能概况

### 1.1 当前瓶颈分析

```
对话请求耗时分布（估算）:
  ┌─────────────────────────────────────────────────┐
  │ LLM API 调用        ██████████████████████ 60%  │
  │ BGE 嵌入 + 检索     ████████ 20%                │
  │ BGE Reranker 重排序  █████ 12%                  │
  │ 数据处理 & 构建Prompt ██ 5%                     │
  │ 其他（会话/日志等）   █ 3%                       │
  └─────────────────────────────────────────────────┘
```

## 2. 优化方向

### 2.1 检索优化（中等收益 ★★★☆☆）

**问题：** 每次对话都执行完整的多路召回（BM25 + TF-IDF + 向量检索）→ RRF 融合 → BGE Rerank

**优化方案：**

| 方案 | 预期提升 | 实现难度 | 说明 |
|------|---------|---------|------|
| 检索结果缓存 | 减少 30% 检索时间 | 低 | 相同问题命中缓存直接返回 |
| BGE 嵌入预计算 | 减少 15% 检索时间 | 低 | 启动时预计算所有文本向量 |
| 多路召回改为2路 | 减少 20% 检索时间 | 低 | BM25 + 向量检索，去掉 TF-IDF |
| 向量检索 TopK 从 100→30 | 减少 10% 检索时间 | 低 | 减少 Reranker 处理量 |

**已实现：** `embedding_cache` (Redis) 缓存相同文本的向量，`hot_qa` (Redis) 缓存热门问答。

### 2.2 LLM 调用优化（高收益 ★★★★★）

**问题：** Kimi API 调用占总耗时 60%，且受网络延迟影响大

| 方案 | 预期提升 | 实现难度 | 说明 |
|------|---------|---------|------|
| 流式响应 (SSE) | 首字延迟 < 500ms | 中 | 改为 `text/event-stream` 流式输出 |
| 多端点负载均衡 | 提高可用性 | 已实现 | 加权轮询 + 最小连接数 |
| 短问题缓存回答 | 减少 10% API 调用 | 低 | 高频问题预置答案 |
| 并发请求池 | 提高 QPS | 中 | 限制最大并发请求数 |

### 2.3 BGE 模型优化（中等收益 ★★★☆☆）

**问题：** BGE-M3 (2GB+) 加载在 GPU 上，推理需要时间

| 方案 | 预期提升 | 实现难度 | 说明 |
|------|---------|---------|------|
| 向量预计算 & 批量存储 | 减少 50% 嵌入调用 | 低 | 离线批量计算好向量存 Milvus |
| ONNX/TensorRT 加速 | 推理速度 2-3x | 高 | 模型导出为 ONNX |
| 半精度推理 (FP16) | 减少 50% 显存 | 已实现 | `model.half()` |
| BGE-M3 → BGE-small | 推理速度 5-10x | 低 | 换小模型，精度略降 |

### 2.4 数据库优化（低收益 ★★☆☆☆）

| 方案 | 预期提升 | 实现难度 | 说明 |
|------|---------|---------|------|
| Milvus 索引优化 | 检索速度 2-3x | 中 | IVF_FLAT → IVF_SQ8 / HNSW |
| MySQL 连接池 | 减少连接开销 | 低 | 使用 `pymysql.pool` |
| Redis Pipeline | 批量读写 2x | 低 | 合并多个 Redis 命令 |

## 3. 已实现优化

### 3.1 系统级优化

| 优化项 | 实现位置 | 效果 |
|--------|---------|------|
| 后台异步初始化 | `online/main.py` | Flask 启动不等待模型加载 |
| 自动端口切换 | `app_monitor.choose_port()` | 端口被占用自动递增 |
| 全局单例 BGE 模型 | `bge_manager.load_bge_models()` | 避免重复加载模型 |
| Redis 向量缓存 | `bge_manager.embed()` | 相同文本不走模型 |
| 短期记忆持久化 | `app_services._persist_short_memory()` | 对话不丢失 |
| 多主机 Milvus 故障转移 | `milvus_manager.connect()` | 高可用 |

### 3.2 代码级优化

| 优化项 | 效果 |
|--------|------|
| `reduce_dimension()` 对 BGE 1024D → 低维 | Milvus 检索加速 |
| 角色知识优先检索 | 减少通用检索开销 |
| RRF 融合参数 k=60 | 平衡多路召回 |
| 输出去套话 | 减少 token 浪费 |

## 4. 推荐优化路线

### Phase 1（1 天，低风险）
- [x] 检索结果加入 Redis 缓存（无需重复检索）
- [ ] 去掉 TF-IDF 检索（保留 BM25 + 向量检索）
- [ ] 向量检索 TopK 从 100 降为 30

### Phase 2（2-3 天，中等风险）
- [ ] 流式响应（SSE 输出，首字快 5-10x）
- [ ] Milvus 索引从 IVF_FLAT 改为 IVF_SQ8
- [ ] MySQL 连接池

### Phase 3（1 周，高风险高收益）
- [ ] LLM 回答缓存（相同问题复用答案）
- [ ] 预计算全量文本向量，存 Milvus 而非运行时嵌入
- [ ] 添加请求队列 + 并发控制
